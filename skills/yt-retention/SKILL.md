# yt-retention

本檔是改編，不是 Jake Schincariol 的官方專案。上游與授權見倉庫根目錄。

停留曲線是平台願意給你的少數誠實回饋。這個工具只讀使用者已經匯出的 CSV。

```bash
python3 retention.py retention.csv --duration 45
python3 retention.py retention.csv --duration 600 --transcript transcript.srt
```

不上網，不登入後台。使用者自己從 YouTube Studio 或其他他有權匯出的報表把檔案存下來。沒有檔就不要編一條曲線。

## 三個不同的問題

- **開頭流失。** 短影音（時長 180 秒以內）看前 3 秒。長片看前 30 秒。低於 25% 算還好，25% 到 40% 是在漏，再高就是流失很大。先改第一句，不是先改剪輯。取的是窗口裡的最低點，不是剛好卡在第 3 秒的那一格。
- **陡降。** 單格掉得特別快。常見是突然自介、突然談合作、或一個沒有預告的轉題。有 `--transcript` 時，工具會附上當時的句子。
- **中段下滑。** 中間緩緩在掉。那是節奏。先剪，不是整支重寫。

百分比橫軸又沒有 `--duration` 時，工具無法把「3 秒」對準格子，只會暫用前 5%，並在結果裡寫明。先補時長，再下結論。

## 交回來的東西

只講最大的一個洞，和一個改法。不要一次列五個。使用者再問，才講剩下的。若開頭還好、中段又平，就說這支片的問題比較像包裝，轉去 `/yt-package`。

這些數字描述這一支已經發生的停留，不能預測下一支。

## 最後一關

這裡不發佈。技能負責寫，使用者自己上傳。每次輸出的最後一行都是：「要發出，還是再改？」
