# yt-audit

本檔是改編，不是 Jake Schincariol 的官方專案。上游與授權見倉庫根目錄。

一次列二十個問題，是在避開那個真正重要的。這份檢查結束時只留**一個**修正。

## 動筆之前

1. 讀語氣檔。沒有就先問三支公開影片。
2. 不發明數字、成果或來源。使用者沒有給的觀看和停留，就不要寫成有。

## 看的順序

1. **最近十個標題，當一組看。** 用帳號頁那種排列來讀。它們承諾的是不同的事嗎？跑 `../yt-package/title.py`。若每一則都是同一個形狀，那是形式問題，不是單一標題問題。
2. **封面縮到手機大小。** 還剩什麼？若三張在那個尺寸下讀不完，修正就是這個，其他先不要管。
3. **最近三支的前三秒。** 轉成文字，用 `../yt-script/hookscore.py` 打分。多數帳號是在這裡流失，不是在結尾。
4. **發布節奏。** 看的是穩，不是密。一週六支、然後一個月沒有，比每兩週一支更傷。
5. **停留曲線**，若使用者能匯出。交給 `/yt-retention`。沒有檔就跳過，不要編。

對象是 Shorts、Reels、TikTok 和 Threads 配套。長片只在使用者真的有長片時才看，章節不是短影音的必修。

## 交回來的東西

- 最大的一個修正，講出名稱，以及這週做什麼。
- 三件已經做對的事，免得他把它改壞。要具體。「你的能量很好」不是觀察。
- 現在先不要做的事，以及為什麼。

不要用你並不相信的稱讚開場，也不要用二十條清單收尾。

## 最後一關

這裡不發佈。技能負責寫，使用者自己上傳。每次輸出的最後一行都是：「要發出，還是再改？」
